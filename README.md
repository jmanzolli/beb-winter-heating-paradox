# Diesel Heating in Zero-Emission Bus Fleets — reproduction package

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21652815.svg)](https://doi.org/10.5281/zenodo.21652815)

Code, inputs, results, and solver logs for:

> **Diesel Heating in Zero-Emission Bus Fleets: Stochastic Planning under Winter Uncertainty**

A two-stage stochastic MILP that jointly selects bus heating and battery
specifications, charging infrastructure, terminal activation, and grid
capacity for a fixed block schedule, with weather-dependent operational
recourse (class-to-block assignment, charging, EVSE-coupled preconditioning,
and electric-vs-FFH heat dispatch).

**Every number, table, and figure in the paper is generated by a script in
this repository from the archived result files. Nothing is transcribed by
hand.**

## Quick start — verify the paper in ~2 minutes

You do **not** need to re-solve anything to check the paper: all solver
outputs are archived in `results/`. This regenerates every table and figure
and runs the automated integrity checks against them.

```bash
git clone https://github.com/jmanzolli/beb-winter-heating-paradox
cd beb-winter-heating-paradox
python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt          # gurobipy, numpy, pandas, matplotlib

cd src
export ROUTE_INPUTS=../configs/route52_inputs_v7.json
export TAB_RES=../results/campaign_v7_results.json
export TAB_DIV=../results/campaign_division_v7.json
export TAB_PROV=../results/provenance_v7.json
export TAB_REL_BASE=../results/rel_v7_econ_cv00.json
export TAB_REL_ZERO=../results/rel_v7_zero_cv00.json
export SUPP_REL_BASE=$TAB_REL_BASE SUPP_REL_ZERO=$TAB_REL_ZERO
export SUPP_REL_FULL=../results/rel_v7_econ_full.json
export FIG_RES=$TAB_RES FIG_DIV=$TAB_DIV
export FIG_DETBAND=../results/detband_v7.json
export FIG_REL_BASE=$TAB_REL_BASE FIG_REL_ZERO=$TAB_REL_ZERO
export CHECK_RES=$TAB_RES CHECK_PROV=$TAB_PROV

python3 check_results_v5.py              # 39 runs: accounting + consistency audit
python3 make_tables_v6.py                # paper Tables II-V
python3 make_supp_tables.py              # supplementary tables
python3 make_fig_m.py                    # paper Figs. 3-5 + supplementary Fig. S6
```

Notes:

* `gurobipy` must be importable (the model module defines the instance), but
  **no Gurobi licence is needed at this level** — nothing is solved.
* `check_results_v5.py` exits 0 with `failures: 0`; its warnings are the
  loose-gap disclosures discussed in the paper.
* Figure scripts also write `figures/verification_tables.md`: every plotted
  value, dumped straight from the records.

## Full reproduction — re-solve the campaigns

Requires a Gurobi licence. Route-scale runs take minutes to hours each; the
division cases run up to 4 h each by design.

Route 52 (the route--band traction interface is built first from the
telemetry, or reuse the archived `configs/traction_v7.json`):

```bash
cd src
python3 make_traction_v7.py            # route means + band factors (needs telemetry)
export ROUTE_INPUTS=../configs/route52_inputs_v7.json
export CAMP_OUT=../results/campaign_v7_results.json

python3 campaign_v5.py                 # baseline, prices, cap frontier, benchmarks,
                                       # sensitivities, warm-started refinement
python3 v7_econ_ops.py                 # baseline operating metrics (fix-design)
REL_RESULTS=$CAMP_OUT REL_POOL=../configs/v7_residual_pool.json \
  REL_DESIGN=econ_lam0 REL_LAM=0 python3 reliability_v5.py 1000
DETBAND_RES=$CAMP_OUT DETBAND_OUT=../results/detband_v7.json \
  python3 detband_check.py             # per-band benchmark feasibility
python3 v7_extra.py                    # severe-factor / FFH-rating variants
                                       # (run per variant instance, see header)
PROV_RES=$CAMP_OUT PROV_OUT=../results/provenance_v7.json \
  python3 make_provenance_v5.py
```

Division scale (case D warm-starts from case C via `DIV_START_FROM`):

```bash
export ROUTE_INPUTS=../configs/garage_inputs_v7.json
DIV_OUT=../results/div_A.json python3 campaign_division_v5.py A
DIV_OUT=../results/div_B.json python3 campaign_division_v5.py B
DIV_OUT=../results/div_C.json python3 campaign_division_v5.py C
DIV_OUT=../results/div_D.json DIV_TLIM=25200 \

  python3 campaign_division_v5.py D
```

## The model in one paragraph

`src/route52_prototype.py` builds the deterministic equivalent: first-stage
integer purchases (buses by battery/heating class, chargers by site and
rating, terminal activation, grid tiers) plus, per weather scenario,
operational recourse (assignment, plug occupancy and charging power,
EVSE-coupled preconditioning bounded by the heater rating, a trip-level heat
balance over electric heat, FFH heat, and the preconditioning credit,
battery dynamics with cold derates and a hard SoC floor, site power against
grid capacity, and billed demand peaks). Objectives: annual resource cost
`F1` and Scope 1 emissions `F2`; policy cases via a carbon price
`F1 + λ·F2` or a lexicographic ε-constraint frontier — phase 1 certifies
minimum cost, phase 2 minimizes emissions within θ = 0.5 kCAD/yr of it.
Reported designs are phase-2 solutions, whose cost may exceed the certified
incumbent by at most that slack.

## Verification

`check_results_v5.py` is the audit entry point. It verifies that scenario
weights sum to 365 days, diesel and emissions accounting, that cost
components sum to `F1`, that carbon payments are excluded from `F1`, cap
satisfaction, fleet coverage, gap consistency, relaxation and carbon-price
monotonicity, the heater-rating bound on preconditioning, and that removed
analyses do not reappear in the manuscript (`CHECK_TEX` selects which
manuscript file to scan).

## Notes on the formulation

Two corrections matter for anyone comparing against earlier versions.
Preconditioning power is bounded by the **electric heater's rated output**,
not by the charging acceptance — the earlier bound allowed several times the
rated output through the cabin heater. And preconditioning heat carries a
thermal-retention coefficient rather than being credited in full at
departure. Both are documented in `docs/REVISION_AUDIT.md`.

## Data availability

Raw TTC telemetry is **not redistributed** (data-use agreement). The
empirical models estimated from it are reproduced in full — the
traction-interface coefficients in `configs/*.json`, the cabin-thermal
coefficients in the paper's appendix and supplementary material — so every
optimization result regenerates without the raw data. Only re-fitting the
empirical models from scratch (`fit_v5_inputs.py`) requires it.
